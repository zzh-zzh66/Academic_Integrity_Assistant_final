### 分层架构

#### 1. 表示层（Presentation Layer）

- **用户接口**：接收用户查询输入
- **响应输出**：返回格式化的答案

#### 2. 业务逻辑层（Business Logic Layer）

- **主图编排**：工作流的整体编排和控制
- **分支处理**：咨询类、行为判断类、混合类分支
- **循环优化**：循环检索和 LLM 增强

#### 3. 数据处理层（Data Processing Layer）

- **术语预处理**：术语标准化和要素提取
- **查询优化**：根据复杂度生成检索策略
- **上下文提取**：提取关键信息和上下文

#### 4. 服务集成层（Service Integration Layer）

- **大语言模型服务**：意图识别、复杂度判断、响应生成
- **知识库检索服务**：向量检索和语义搜索
- **对象存储服务**：文件存储和管理

#### 5. 数据存储层（Data Storage Layer）

- **知识库**：学术规范和案例数据
- **配置文件**：节点配置和检索策略
- **日志文件**：运行日志和调试信息

## 数据流

### 查询处理流程

```
用户查询
   │
   ├─→ 复杂度判断
   │       ├─→ 输入：user_query
   │       └─→ 输出：query_complexity (simple/standard/complex)
   │
   ├─→ 意图识别
   │       ├─→ 输入：user_query
   │       └─→ 输出：intent_type (咨询类/行为判断类/混合类)
   │
   ├─→ 术语预处理
   │       ├─→ 输入：user_query
   │       └─→ 输出：refined_query, refined_keywords, behavior_elements
   │
   ├─→ 意图分流
   │       │
   │       ├─→ 咨询类分支
   │       │       ├─→ 查询优化
   │       │       │       ├─→ 输入：refined_query, refined_keywords, query_complexity
   │       │       │       └─→ 输出：optimized_query, retrieval_strategy
   │       │       │
   │       │       └─→ 循环检索子图
   │       │               ├─→ 输入：user_query, optimized_query, retrieval_strategy
   │       │               └─→ 输出：retrieval_results
   │       │
   │       ├─→ 行为判断类分支
   │       │       ├─→ 行为判断分析
   │       │       │       └─→ 输出：enhanced_query, behavior_elements
   │       │       │
   │       │       ├─→ 知识库检索
   │       │       │       └─→ 输出：retrieval_results
   │       │       │
   │       │       ├─→ 上下文扩展
   │       │       │       └─→ 输出：expanded_context
   │       │       │
   │       │       ├─→ 重排序
   │       │       │       └─→ 输出：ranked_results
   │       │       │
   │       │       └─→ 置信度评估
   │       │               └─→ 输出：confidence_score, judgment_result
   │       │
   │       └─→ 混合类分支
   │               ├─→ 查询拆分
   │               │       └─→ 输出：consult_query, judge_query, shared_context
   │               │
   │               ├─→ 咨询子图（复用咨询类分支逻辑）
   │               │       └─→ 输出：consult_results
   │               │
   │               ├─→ 判断子图（复用行为判断类分支逻辑）
   │               │       └─→ 输出：judge_results
   │               │
   │               └─→ 结果整合
   │                       └─→ 输出：integrated_results
   │
   └─→ 响应生成
           ├─→ 输入：user_query, intent_type, retrieval_results
           └─→ 输出：formatted_response
```

### 循环检索数据流

```
循环检索子图开始
   │
   ├─→ 第1轮
   │       ├─→ 知识库检索（top_k=15, min_score=0.3）
   │       ├─→ 内容扩展（扩展为完整段落）
   │       ├─→ 重排序（多维度评分）
   │       ├─→ 上下文提取（提取关键信息）
   │       ├─→ 改善分析（评估改善潜力）
   │       └─→ 循环判断（决定是否继续）
   │
   ├─→ 第2轮（如果继续）
   │       ├─→ 知识库检索（top_k=10, min_score=0.6）
   │       ├─→ 内容扩展
   │       ├─→ 重排序
   │       ├─→ 上下文提取
   │       ├─→ 改善分析
   │       └─→ 循环判断
   │
   └─→ 第3轮（如果继续）
           ├─→ 知识库检索（top_k=8, min_score=0.7）
           ├─→ 内容扩展
           ├─→ 重排序
           ├─→ 上下文提取
           ├─→ 改善分析
           └─→ 循环判断
```

## 模块设计

### 单一职责原则

每个模块只负责一个明确的功能：

| 模块 | 职责 |
|------|------|
| **complexity_node** | 判断查询复杂度 |
| **intent_recognition_node** | 识别意图类型 |
| **term_preprocessing_node** | 术语预处理 |
| **consult_query_optimize_node** | 咨询类查询优化 |
| **judge_process_node** | 行为判断分析 |
| **mixed_process_node** | 混合类查询拆分 |
| **response_generation_node** | 响应生成 |

### 高内聚低耦合

- **高内聚**：相关功能集中在同一模块
- **低耦合**：模块之间通过状态对象传递数据，减少直接依赖

### 配置驱动

所有提示词和参数通过 JSON 配置文件管理：

- **模型配置**：模型参数（温度、top_p、max_tokens等）
- **提示词配置**：系统提示词和用户提示词
- **检索配置**：检索策略和参数

### 类型安全

使用 Pydantic 确保类型安全：

```python
from pydantic import BaseModel, Field

class NodeInput(BaseModel):
    """节点输入"""
    user_query: str = Field(..., description="用户查询")
    
class NodeOutput(BaseModel):
    """节点输出"""
    result: str = Field(..., description="处理结果")
```

## 性能优化

### 1. 减少循环轮次

**策略**：
- 简单问题：1轮检索
- 标准问题：2轮检索
- 复杂问题：3轮检索

**效果**：
- 响应时间减少 30-50%
- 成本降低 40-60%

### 2. 提前退出机制

**策略**：
- 当 top_score ≥ 0.85 时提前退出
- 当 top_3_avg ≥ 0.75 时提前退出
- 确保至少完成1轮检索

**效果**：
- 平均响应时间减少 20-30%

### 3. 并行处理

**策略**：
- 意图识别和术语预处理并行执行
- 混合类分支的咨询和判断部分并行执行

**效果**：
- 响应时间减少 15-25%

### 4. 缓存机制

**策略**：
- 对相同查询启用缓存
- 缓存过期时间：1小时
- 缓存大小：1000条

**效果**：
- 重复查询响应时间减少 80-90%

### 5. 批量处理

**策略**：
- 批量调用知识库检索
- 批量处理结果扩展

**效果**：
- 知识库检索时间减少 20-30%

## 安全考虑

### 1. 输入验证

```python
from pydantic import BaseModel, Field, validator

class GraphInput(BaseModel):
    """工作流输入"""
    user_query: str = Field(..., description="用户查询")
    
    @validator('user_query')
    def validate_query(cls, v):
        if not v or not v.strip():
            raise ValueError("用户查询不能为空")
        if len(v) > 1000:
            raise ValueError("用户查询长度不能超过1000字符")
        return v.strip()
```

### 2. 输出过滤

```python
def filter_response(response: str) -> str:
    """过滤响应中的敏感信息"""
    # 移除系统内部信息
    response = re.sub(r'\[.*?\]', '', response)
    # 移除HTML标签
    response = re.sub(r'<[^>]+>', '', response)
    return response
```

### 3. 错误处理

```python
try:
    result = main_graph.invoke({"user_query": user_query})
except Exception as e:
    logger.error(f"工作流执行失败: {e}")
    return {"error": "服务暂时不可用，请稍后重试"}
```

### 4. 日志记录

```python
import logging

logger = logging.getLogger(__name__)

def log_request(user_query: str):
    """记录请求日志"""
    logger.info(f"收到查询: {user_query[:100]}...")

def log_response(response: str):
    """记录响应日志"""
    logger.info(f"生成响应: {response[:100]}...")
```

## 扩展性

### 1. 新增节点

遵循以下步骤：

1. 在 `state.py` 中定义节点输入输出
2. 在 `nodes/` 目录下实现节点
3. 创建配置文件
4. 在 `graph.py` 中添加节点和边
5. 导出节点

### 2. 新增分支

遵循以下步骤：

1. 定义新的意图类型
2. 实现分支节点
3. 添加条件判断逻辑
4. 在主图中添加分支路由
5. 测试和优化

### 3. 新增子图

遵循以下步骤：

1. 在 `loop_graph.py` 中定义子图状态
2. 实现子图节点
3. 编排子图
4. 编译子图
5. 在主图中调用子图

### 4. 新增集成

遵循以下步骤：

1. 查看可用集成服务
2. 使用 `integration_detail` 获取集成详情
3. 根据文档实现集成调用
4. 在节点中使用集成
5. 测试和验证

## 总结

学术诚信助手工作流的技术架构具有以下特点：

1. **模块化设计**：单一职责原则，高内聚低耦合
2. **配置驱动**：所有提示词和参数通过配置文件管理
3. **类型安全**：使用 Pydantic 确保类型安全
4. **性能优化**：循环优化、提前退出、并行处理、缓存机制
5. **安全考虑**：输入验证、输出过滤、错误处理、日志记录
6. **扩展性**：易于添加新节点、新分支、新子图、新集成
